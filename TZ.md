# JobHub — платформа поиска работы и сотрудников

**Версия:** 1.0  
**Тип проекта:** Веб-приложение  
**Уровень сложности:** Продвинутый  
**Основная технология:** Next.js  
**Статус:** Планирование

## 1. Общая информация

### 1.1. Название проекта

**JobHub** — современная онлайн-платформа для поиска работы, публикации вакансий и взаимодействия работодателей с соискателями.

### 1.2. Цель проекта

Разработать удобное, безопасное и адаптивное веб-приложение, которое позволит соискателям находить подходящие вакансии, а работодателям — искать сотрудников.

### 1.3. Целевая аудитория

- Студенты, ищущие стажировки и первую работу.
- Специалисты, ищущие новые карьерные возможности.
- Компании и HR-менеджеры.
- Рекрутинговые агентства.
- Администраторы и модераторы платформы.

### 1.4. Основные задачи

1. Реализовать регистрацию и авторизацию.
2. Создать систему ролей и прав доступа.
3. Разработать каталог вакансий.
4. Реализовать создание и редактирование резюме.
5. Добавить систему откликов.
6. Создать личные кабинеты.
7. Реализовать чат между работодателями и соискателями.
8. Добавить уведомления.
9. Создать систему модерации.
10. Разработать административную панель и аналитику.

## 2. Роли пользователей

В системе предусмотрено пять ролей.

### 2.1. Гость (Guest)

Неавторизованный посетитель.

**Возможности:**
- Просматривать главную страницу.
- Просматривать опубликованные вакансии.
- Искать вакансии.
- Использовать фильтры.
- Просматривать публичные страницы компаний.
- Регистрироваться.
- Входить в аккаунт.

**Ограничения:**
- Не может откликаться на вакансии.
- Не может создавать резюме.
- Не может отправлять сообщения.
- Не имеет доступа к личным кабинетам.

### 2.2. Соискатель (Job Seeker)

Зарегистрированный пользователь, который ищет работу.

**Возможности:**
- Редактировать профиль.
- Загружать аватар.
- Создавать несколько резюме.
- Указывать навыки, образование и опыт работы.
- Прикреплять PDF-резюме.
- Искать и фильтровать вакансии.
- Добавлять вакансии в избранное.
- Откликаться на вакансии.
- Прикреплять сопроводительное письмо.
- Просматривать историю откликов.
- Отслеживать статус отклика.
- Общаться с работодателем через чат.
- Получать уведомления.
- Подавать жалобы на подозрительные вакансии.

### 2.3. Работодатель (Employer)

Представитель компании, публикующий вакансии.

**Возможности:**
- Создавать профиль компании.
- Редактировать информацию о компании.
- Добавлять логотип компании.
- Создавать вакансии.
- Редактировать и закрывать вакансии.
- Отправлять вакансии на модерацию.
- Просматривать отклики кандидатов.
- Просматривать резюме откликнувшихся пользователей.
- Изменять статусы откликов.
- Приглашать кандидатов на собеседование.
- Общаться с кандидатами через чат.
- Просматривать статистику вакансий.
- Получать уведомления.

### 2.4. Модератор (Moderator)

Пользователь, отвечающий за качество и безопасность контента.

**Возможности:**
- Просматривать вакансии, ожидающие проверки.
- Одобрять или отклонять вакансии.
- Указывать причины отклонения.
- Проверять жалобы пользователей.
- Скрывать вакансии, нарушающие правила.
- Проверять публичные профили компаний.
- Выдавать предупреждения.
- Передавать серьёзные нарушения администратору.
- Просматривать историю модерации.

**Ограничения:**
- Не может назначать администраторов.
- Не может изменять системные настройки.
- Не имеет доступа к паролям пользователей.
- Не может удалять системные журналы.

### 2.5. Администратор (Admin)

Пользователь с расширенными правами управления платформой.

**Возможности:**
- Управлять пользователями.
- Назначать и изменять роли.
- Блокировать и разблокировать аккаунты.
- Управлять компаниями.
- Просматривать все вакансии.
- Управлять категориями вакансий.
- Рассматривать жалобы.
- Просматривать системную аналитику.
- Управлять тарифами и подписками.
- Просматривать журнал действий модераторов.
- Изменять настройки платформы.

## 4. Функциональные требования

### 4.1. Регистрация и авторизация

Система должна поддерживать:

- Регистрацию по email и паролю.
- Вход в аккаунт.
- Выход из аккаунта.
- Подтверждение email.
- Восстановление пароля.
- Защиту приватных страниц.
- Проверку ролей пользователей.
- Управление пользовательскими сессиями.

**Правила:**
- Email должен быть уникальным.
- Пароль должен содержать минимум 8 символов.
- Пароли должны храниться в виде безопасных хешей.
- Роли Moderator и Admin назначаются только администратором.
- Пользователь не должен иметь возможности самостоятельно повысить свои права.

### 4.2. Система вакансий

Каждая вакансия должна содержать:

- Название должности.
- Название компании.
- Описание работы.
- Требования к кандидату.
- Обязанности.
- Условия работы.
- Город.
- Формат работы: офис, удалённо, гибрид.
- Тип занятости: полная, частичная, стажировка.
- Зарплату или диапазон зарплаты.
- Требуемый опыт работы.
- Дату публикации.
- Статус вакансии.

**Статусы вакансий:**
- Draft — черновик.
- Pending — ожидает модерации.
- Published — опубликована.
- Rejected — отклонена.
- Closed — закрыта.
- Archived — архивирована.

Работодатель может изменять только вакансии своей компании. Существенное изменение опубликованной вакансии должно отправлять её на повторную модерацию.

### 4.3. Поиск и фильтрация

Пользователь должен иметь возможность искать вакансии по:

- Названию должности.
- Ключевым словам.
- Компании.
- Городу.
- Зарплате.
- Типу занятости.
- Формату работы.
- Опыту работы.
- Дате публикации.

Дополнительно:
- Сортировка по дате и зарплате.
- Пагинация результатов.
- Сохранение выбранных фильтров.
- Отображение количества найденных вакансий.

### 4.4. Система резюме

Соискатель может создавать и редактировать резюме.

**Поля резюме:**
- Имя и фамилия.
- Желаемая должность.
- Город.
- Контактная информация.
- Навыки.
- Образование.
- Опыт работы.
- Языки.
- Описание о себе.
- Ссылка на портфолио.
- Прикреплённый PDF-файл.

Соискатель может создавать несколько резюме и выбирать нужное при отклике.

Резюме не должно быть публично доступным без разрешения владельца.

### 4.5. Система откликов

Соискатель может откликаться на опубликованные вакансии.

При отклике необходимо:
1. Выбрать резюме.
2. При необходимости написать сопроводительное письмо.
3. Подтвердить отправку отклика.

**Статусы отклика:**
- Submitted — отправлен.
- Viewed — просмотрен.
- Interview — приглашение на собеседование.
- Accepted — принят.
- Rejected — отклонён.
- Withdrawn — отозван соискателем.

Работодатель может изменять статусы откликов на свои вакансии.

Соискатель должен видеть актуальный статус своего отклика.

### 4.6. Чат

Необходимо реализовать обмен сообщениями между соискателем и работодателем.

**Функции:**
- Отправка текстовых сообщений.
- История переписки.
- Отображение времени отправки.
- Индикатор непрочитанных сообщений.
- Уведомления о новых сообщениях.
- Обновление сообщений в реальном времени.

Чат создаётся в контексте отклика. Доступ к нему имеют только соответствующий соискатель и уполномоченные представители работодателя.

### 4.7. Уведомления

Пользователи должны получать уведомления о важных событиях.

**Соискатель:**
- Изменение статуса отклика.
- Приглашение на собеседование.
- Новое сообщение.
- Новые вакансии по сохранённому поиску.

**Работодатель:**
- Новый отклик.
- Новое сообщение.
- Результат модерации вакансии.

**Модератор:**
- Новая вакансия на проверку.
- Новая жалоба.

**Администратор:**
- Критические события системы.
- Жалобы, переданные на рассмотрение.

Уведомления отображаются внутри сайта. Email-уведомления могут быть включены в настройках.

### 4.8. Жалобы и модерация

Пользователи могут отправлять жалобы на вакансии и компании.

Жалоба содержит:
- Объект жалобы.
- Причину.
- Описание проблемы.
- Дату создания.
- Статус рассмотрения.

**Статусы жалоб:**
- Open.
- In Review.
- Resolved.
- Rejected.

Модератор должен фиксировать принятое решение и его причину.

### 4.9. Административная панель

Административная панель должна содержать:

- Общее количество пользователей.
- Количество работодателей.
- Количество опубликованных вакансий.
- Количество откликов.
- Количество жалоб.
- Количество заблокированных пользователей.
- Графики активности.
- Управление ролями.
- Управление категориями.
- Журнал административных действий.

### 4.10. Подписки

Предусмотреть возможность платных тарифов для работодателей.

**Free:**
- Ограниченное количество активных вакансий.
- Базовая статистика.

**Premium:**
- Увеличенный лимит вакансий.
- Расширенная аналитика.
- Продвижение вакансий.

На первом этапе можно реализовать тарифы без реальных платежей. Подключение платёжной системы выполняется отдельно.
