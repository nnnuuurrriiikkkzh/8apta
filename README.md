# JobHub — UI платформы поиска работы

Next.js 16, React 19, TypeScript и Tailwind CSS 4. Реализованы все 36 типов страниц из раздела 5 ТЗ и 6 дополнительных экранов — всего 42 типа страниц, без учёта отдельных ID вакансий/компаний и служебной 404.

Это учебная версия интерфейса: компании, пользователи и вакансии вымышлены. Действия связаны общим состоянием в браузере. База данных, API, настоящая авторизация, отправка писем и платежи не подключены.

## Запуск

В PowerShell:

```powershell
npm.cmd ci
npm.cmd run dev
```

Сайт: http://localhost:3000. Если порт занят: `npm.cmd run dev -- --port 3001`.

Проверка production-сборки:

```powershell
npm.cmd run build
npm.cmd run start
```

Используется Webpack и `@tailwindcss/postcss`: в этой среде Windows Turbopack ранее завершался ошибкой обработки CSS. Файл `AGENTS.md` содержит инструкции для установленной версии Next.js.

## Вход и роли

При регистрации выбери «Найти работу» или «Найти сотрудника». После заполнения формы откроется главная. Кнопка «Войти» в шапке заменится на «Кабинет» и будет вести в кабинет выбранной роли. Пункта «Работодателю» в общем меню нет. Повторный вход сохраняет роль последней регистрации в этом браузере.

Для проверки подходят вымышленный email и любой тестовый пароль от 8 символов. Пароль и email входа не сохраняются. Форма проверяет формат, но не проверяет существование аккаунта. Профили и данные общие для деморежима, они не привязаны к введённому email.

Обычные кабинеты показывают экран входа гостю и переход в свой кабинет при несовпадении роли. Это клиентские UI-состояния, а не защита данных. В рабочих кабинетах нет переключателя роли. Для просмотра служебных сценариев открой `/moderator` или `/admin`; в этих демонстрационных панелях есть переключатель. Серверная проверка прав потребует отдельной реализации.

## Что работает в UI

- Каталог: поиск по должности, компании и навыкам; город, направление, формат, опыт, зарплата, занятость и дата; сортировка, пагинация, счётчик, фильтры в URL, скрытие панели и пустая выдача. Сохранённые поиски с уведомлением при подходящей локальной публикации.
- Компании: поиск, город, описание, вакансии компании, жалобы. Изменения компании отражаются на публичной странице.
- Соискатель: профиль и аватар, несколько резюме, редактирование, предпросмотр, PDF, удаление с подтверждением, избранное, история откликов и отзыв заявки.
- Отклик: выбор существующего резюме, письмо, подтверждение передачи копии. Сохраняется снимок резюме — последующее редактирование оригинала не меняет уже отправленную заявку. Повторный активный отклик запрещён; после отзыва можно отправить новый.
- Работодатель: демонстрационная компания «Линия», профиль и логотип; создание и редактирование вакансий; черновик, проверка, публикация, отклонение, закрытие и архив; просмотр резюме кандидатов, изменение статусов, чат, аналитика и CSV.
- Модерация: одобрение/отклонение с причиной, повторная проверка после правок, проверка компаний, жалобы, скрытие материала, предупреждения, передача администратору и журнал решений.
- Чат: диалоги по откликам, отправка текста, история, время, непрочитанные, уведомления. Общие вкладки браузера получают обновления через событие `storage`.
- Уведомления: статусы откликов, сообщения, модерация, жалобы и сохранённые поиски; отметка прочитанного, массовое прочтение и фильтр.
- Админ-панель: поиск пользователей, назначение ролей и блокировка как демосостояние, защита от отключения последнего активного администратора; компании, вакансии, категории, жалобы, статистика, журнал, тарифы Free/Premium и системные настройки.
- Настройки: предпочтения уведомлений, UI приватности, проверка формы смены пароля и завершение локального входа. Восстановление и подтверждение email имеют отдельные демонстрационные экраны.
- Формы показывают валидацию, результат сохранения и ошибки хранилища. Предусмотрены отмена, подтверждение действий, пустые состояния, мобильная навигация и клавиатурный фокус в диалогах.

## Заполненный кабинет соискателя

Кабинет сразу показывает вымышленного Александра Кима: три резюме (UI/UX, Frontend и контент), четыре отклика (новая заявка, просмотрено, собеседование и отказ), три избранные вакансии, диалоги с компаниями и шесть уведомлений. Настройки уведомлений заполнены начальными предпочтениями, поля паролей остаются пустыми.

Начни с «Обзора» → «Последние отклики» → «Переписка». В «Моих откликах» можно открыть снимок резюме и письмо, отозвать заявку или продолжить диалог. Сообщения отправляются локально, уведомления отмечаются прочитанными, примеры резюме редактируются как обычные записи.

Данные примеров находятся в `lib/seeker.ts` и `lib/seeker-demo.ts`. Для уже использовавшегося браузера выполняется совместимое дополнение: существующие профиль, резюме, отклики и настройки сохраняются; на вакансию с уже имеющимся личным откликом второй пример не создаётся. После изменения данных сохраняется версия набора, поэтому удалённые примеры не возвращаются при обновлении. Старое избранное дополняется примерами один раз при переходе на новый формат хранения.

## Локальные данные и ограничения

| Ключ localStorage | Данные |
| --- | --- |
| `jobhub-demo-session` | Текущая UI-роль; старое значение `active` совместимо с ролью соискателя |
| `jobhub-demo-account-role` | Роль последней демонстрационной регистрации |
| `jobhub-seeker-v1` | Профиль и резюме, включая вложения |
| `jobhub-platform-v1` | Вакансии, компании, отклики, сообщения, уведомления, жалобы, история и настройки |
| `jobhub-favorites` | ID избранных вакансий |

Статусы заявок старого интерфейса из `jobhub-demo-application-statuses` читаются при первом переходе к общему хранилищу.

Аватар и логотип: PNG/JPEG/WebP до 512 КБ; PDF резюме — до 1 МБ с проверкой сигнатуры. Переполнение localStorage выводит ошибку, не выдавая неуспешную операцию за сохранённую. Выход не удаляет рабочие данные. Используй тестовую информацию: локальное хранилище доступно пользователю браузера.

Работодатель управляет компанией «Линия» и видит её заявки; остальные компании нужны для каталога. Аналитика вычисляется из локальных записей, без выдуманной статистики просмотров. Пользователи, назначения ролей, блокировки аккаунтов и системные параметры демонстрируют административные состояния, но не управляют настоящими аккаунтами. Email, видимость публичного профиля и ограничения тарифов показаны в UI; отправка писем, публикация резюме, платёжная система, реальные сессии и права доступа требуют backend.

## Проверка сценариев

1. Зарегистрируйся как соискатель и открой «Мои отклики»: там уже есть четыре примера. Для нового отклика выбери вакансию без заявки, например «Project Manager», и приложи резюме.
2. Для просмотра второй стороны зарегистрируйся как работодатель в том же браузере. В «Откликах кандидатов» найди заявку, измени статус и отправь сообщение.
3. Вернись к роли соискателя через регистрацию и проверь уведомление, чат и возможность отозвать заявку. Данные сохраняются между сменами демонстрационной роли.
4. В кабинете работодателя создай вакансию и отправь на модерацию. На `/moderator/jobs` одобри её. Вакансия появится в каталоге и будет доступна по собственному URL.
5. Отправь жалобу со страницы вакансии. Рассмотри её на `/moderator/reports`, скрой публикацию и проверь журнал и уведомления.
6. Проверь каталог на мобильном экране, скрытие/раскрытие фильтров, сохранённый поиск, избранное и пустые состояния.

## Структура исходников

- `app/` — маршруты, layouts, метаданные и общие стили.
- `components/site.tsx` — шапка, подвал и навигация по роли.
- `components/auth/` — формы и локальное состояние входа.
- `components/seeker/` — профиль и редактор резюме.
- `components/platform/` — кабинеты, управление вакансиями, компании, модерация, админ-панель, чат, уведомления и общий store.
- `lib/jobs.ts`, `lib/applications.ts`, `lib/seeker.ts` — исходные демонстрационные данные.
- `lib/platform.ts` — типы и общие данные платформы.
- `TZ.md` — исходное ТЗ полной системы. Покрытие UI-страниц не означает выполнение backend-требований ТЗ.
